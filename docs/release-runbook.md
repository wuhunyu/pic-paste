# PicPaste macOS 1.0 Candidate Preparation (P6-T1)

**Scope: identity, source version, icon and development packaging only.**
This file does NOT authorize publication, signing or treating CI as physical
device acceptance.

## Candidate metadata

- App Bundle ID: com.wuhunyu.picpaste. Before signing, confirm this identifier
  is owned/approved in the real Apple Developer account.
- Workspace and CFBundleShortVersionString: 1.0.0.
- CFBundleVersion: 10000. Minimum macOS: 14.0.
- Icon: a deterministic, original screenshot/pin symbol generated by
  scripts/build_macos_icon.py, with RGBA PNG resolutions from 16 to 1024
  inside an ICNS container. No network or third-party Python packages.
- **This is NOT a public 1.0 build merely because its metadata says 1.0.0.**
  The existing Lite/Full/Canary ZIPs remain UNSIGNED-DEV (ad-hoc signatures).

**TCC/identity migration:** Switching from com.example.picpaste to
com.wuhunyu.picpaste changes the app identity for Screen Recording
permissions and can separate settings/restoration records. Test an upgrade
and a clean install on real macOS 14/26. Do NOT silently delete user PNGs,
settings or permissions to conceal migration failures.

## Commands

Python 3.11+ is required for stdlib TOML parsing.

~~~bash
python3 scripts/release_metadata.py --root .
python3 -m unittest discover -s tests -p 'test_release_identity.py' -v
python3 scripts/build_macos_icon.py --output dist/.resources/PicPaste.icns
cargo test --workspace --locked

# On macOS after compilation (or the macOS GitHub Actions runner):
PICPASTE_VARIANT=Lite bash scripts/package-macos.sh
PICPASTE_VARIANT=Full bash scripts/package-macos.sh
/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' dist/Lite/PicPaste.app/Contents/Info.plist
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' dist/Lite/PicPaste.app/Contents/Info.plist
test -s dist/Lite/PicPaste.app/Contents/Resources/PicPaste.icns
codesign --verify --deep --strict dist/Lite/PicPaste.app
~~~

Packaging rejects mismatched Cargo/lock/plist BEFORE deleting the existing
output app, adds the icon to Contents/Resources, and caches the generated ICNS
only while its source generator SHA is unchanged. A user may override it with
PICPASTE_ICON_BINARY pointing to a regular ICNS file; missing, symlinked or
invalid-header assets fail closed. Normal output filenames retain the
-UNSIGNED-DEV suffix. The optional native Canary is not a default backend.

## Release gates not satisfied by this task

1. Confirm Bundle ID ownership, Developer ID Application identity and
   notarytool Keychain profile.
2. Freeze the FINAL source SHA including identifier/version/icon changes.
   Repeat real macOS14/26 GUI, Retina, IME, TCC, Pin/PNG and performance
   acceptance on that exact SHA. Collect real 50-scroll and 400-OCR datasets.
3. Run scripts/release_evidence_gate.py on measured files; review physical
   provenance, not just synthetic CI tests.
4. Build and sign ARM64/x86_64 Universal 2 Lite and Full and matched OCR
   Add-on with one Apple Team ID, then notarize/staple and Gatekeeper-test
   real downloaded packages on a clean machine.
5. Preserve last signed rollback build and SHA256. Only after every gate passes
   create an immutable v1.0.0 Git tag and GitHub Release.

Do NOT store developer signing keys, passwords or notary credentials in this
repository. See release-evidence-runbook.md for physical report requirements.

## Rollback

Keep the stable eframe backend and prior development package available.
Revert this PR if candidate metadata introduces compatibility failures.
Because the Bundle ID changes, any restored older build may require explicit
Screen Recording authorization; do not disable Gatekeeper or clear user data.

## P6-T2: Developer ID and notarization candidate infrastructure

See the [signed candidate runbook](signed-release-candidate-runbook.md).
The `scripts/release-macos-signed.sh` command requires a clean checkout
at the manually approved QA source SHA, real measurement reports, a
separately hash-bound human approval, Apple Team-matched Developer ID
certificate and Keychain notary profile. After fresh Universal 2 builds
it signs nested OCR/helper/main/outer bundle in order, checks runtime and
Team ID, requires Notary Accepted, staples the .app and assembles
`*-CANDIDATE.zip` with checksums.

The script **does not** create a release tag, public GitHub Release or
replace an installed app. Real Intel/Apple Silicon downloaded-package
Gatekeeper/TCC/upgrade/rollback testing and final release approval remain
blocked in P6-T3. The standalone notarized OCR helper ZIP cannot have a
stapler ticket attached to the raw executable. Keep private QA and Apple
credentials out of the public repository and Actions artifacts.
